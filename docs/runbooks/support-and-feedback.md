# Support and feedback runbook

> **DRAFT, agent-drafted, unreviewed, not legal advice; owner reviews and signs later.**

Source: E24-T7 in `docs/audit/plans/E24-plan.md`.

## Mailbox checks

- Check the support mailbox at least weekly. This matches the E19 plan (E19 O3).
- Keep an autoresponder on the mailbox so senders know their message was received and how long a reply takes.

## Complaints

- Acknowledge each complaint within 30 days. The timing follows the E19 plan (s164A).
- Keep the complaint wording on `/contact` in line with the approved copy (E19, owner step O6).
- Do not treat this runbook as a statement of the legal position. The owner and the solicitor confirm it.

## Feedback to issues

- Turn user feedback into a GitHub issue with the `needs-triage` label. The label set is in `docs/agents/triage-labels.md`.
- Write the issue from the feedback text only. Do not add the sender's email address or account details.

## Data handling

- **Never paste user financial data into issues.** This includes account names, balances, transaction lines, card or account numbers, and screenshots that show them.
- If a message contains financial data, reply to the user asking them not to send it again, and do not copy it anywhere.
- Personal data handling is covered by the data map in `docs/legal/data-map.md`.
