# E18 Phase 0 (A-01 to A-04) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Ship the agent-side prerequisites for the first production deploy (release PR 368): ops scripts and an owner runbook, backend readiness endpoint, graceful shutdown, web/marketing health routes and noindex.

**Architecture:** Small independent changes. Backend gets a public `HealthController` (no auth, no DB detail leakage) and `enableShutdownHooks`. Web gets resource routes `/healthz` and `/robots.txt`; marketing gets an exported express router (`/healthz`, `/robots.txt`) plus a noindex header middleware, both honouring `ALLOW_INDEXING=true`. Ops scripts live in `scripts/ops/`, print counts only, and are tested against a throwaway local Postgres.

## Review Focus

- `/health/ready` 503 body is exactly `{"status":"unavailable"}` (no error text) and `SELECT 1` hanging must time out (2s) rather than hang the healthcheck.
- `RAILWAY_GIT_COMMIT_SHA` unset or empty gives `commit: "unknown"`.
- `/robots.txt` and `X-Robots-Tag` on marketing must come before the SPA catch-all, and `ALLOW_INDEXING` must be exactly `"true"` to lift them.
- Ops scripts refuse non-local DBs in tests and never echo `$PGURL`/passwords.
