# Marketing site pre-release pass (2026-11-14)

In-depth functional and visual check of `apps/marketing` on `origin/main` at `42acb397`, before the next release. The previous, lighter sweep is in [`../prerelease/REPORT.md`](../prerelease/REPORT.md).

## Scope and method

- **Routes**: from `src/App.tsx`, `src/utils/toolSlugs.ts` (`STATIC_PATHS`, `CANONICAL_TOOL_SLUGS`, `TOOL_SLUG_ALIASES`) and `server/sitemap.ts`. Sitemap = 6 static pages + 8 calculators. Also checked: one alias (`/tools/mortgage-overpay-vs-isa-calculator`), an unknown path (404), case and trailing-slash variants.
- **Servers**: marketing dev (`bun server.ts`) and production build (`bun run build`, `NODE_ENV=production`), web dev and backend dev, all local. A third production instance with `ALLOW_INDEXING=true FLUMP_LAUNCH=true SITE_URL=…` refused to boot because business details are still placeholders, which is the intended launch guard.
- **Sweep**: headless Chromium (Playwright), every route at 375, 768 and 1280, light and dark, JavaScript on and off: 192 production page loads + 64 dev loads. Checked HTTP status, horizontal overflow, console and page errors, failed requests, hydration warnings, `<title>`, meta description, canonical, Open Graph, Twitter card, `robots`, `X-Robots-Tag`, one `<h1>`, image `alt`, unlabelled inputs, dead `#anchors`, JSON-LD validity. Full-page screenshots of every combination were taken (scratchpad); the ones cited below are in `shots/`.
- **Links**: every unique `href` on every page fetched (internal, app, external, mailto inspected). Web `/tools/<slug>` checked for every marketing slug.
- **Accessibility**: axe-core 4.14 (WCAG 2.2 AA + best practice) on every route, light and dark, 375 and 1280; keyboard tab order and visible focus on home, pricing and three calculators; mobile drawer open, links, Escape and focus return.
- **Maths**: each calculator's defaults and edge values (0, negative, very large, decimals, empty) run through `@flump/finance-engine` directly and compared with what the page shows; source read for maths done outside the engine.
- **Claims and copy**: full rendered text of every page read against the code (`apps/web`, `apps/backend`, `packages/mcp`, `packages/finance-engine`) and the tone and advice-boundary rules.
- **Lighthouse** 12.8.2 (mobile and desktop) on home, pricing, tools index and two calculators; security headers on SSR responses.

- **"Token-bucket safety limits"**: the limiter in `packages/mcp/src/auth/rate-limiter.ts` is a fixed-window counter (60/min, 300/hour). The numbers are right; "token bucket" is not quite. Not changed.
- **Log in / Request invite**: locally the app's `/login` lands on WorkOS "redirect URI invalid" because `localhost:5610` is not a registered redirect. Environment only; slugs and routes are correct.
- **Live demo** (`/sandbox`, new tab) and GOV.UK Tax-Free Childcare link resolve. `/contact#beta` anchor exists. All `mailto:` links carry only a subject, no personal data.
- **No forms**: the marketing site has no form or email capture. Invite, feedback, support, privacy and complaints all go by `mailto:`. Nothing is posted anywhere.

## Security headers (production SSR)

`Strict-Transport-Security: max-age=31536000; includeSubDomains`, a nonce-based `Content-Security-Policy` (`script-src 'self' 'nonce-…'`, `connect-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, no `X-Powered-By`. `style-src` allows `'unsafe-inline'` (needed by inline styles in several components). No `Cross-Origin-Opener-Policy`; optional.
